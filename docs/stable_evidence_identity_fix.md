# 稳定来源标识修复（2026-09-27）

## 行为与边界

修复知识库多轮回答把历史 C1 当作本轮 C1 的问题。生成器现在引用 `[S_...]` 稳定片段标识，
后端按当前已授权检索资料解析，再转换为接口正文中的 `[C1]`、`[C2]` 编号；2026-09-28 起前端进一步将它们映射为每条回答独立的论文式上标 `[1]`、`[2]`。
标识由 source_id、document_id、version、chunk_id 和完整片段内容共同生成（SHA-256 前 24 位）。
检索顺序改变不影响标识；文档、版本、片段或正文改变则产生新标识。

- 当前资料构成唯一允许集合。旧版本、未知、非规范或未闭合来源标识，以及生成器直接输出的
  页面 C 编号，转换为无效标记，由结构校验阻止交付，不静默删除后放行。
- 引用快照新增 `evidence_id`；提交消息、完成结果及历史 JSON 保留该字段，页面类型为可选字段。
  接口与存储仍保留 C 编号，页面显示 `[1]` 等阅读编号，不展示长哈希。
- 历史消息仅在模型输入副本中标注“历史引用”。快照标识仍在当前允许集合时才提供对应稳定标识；
  无标识的旧记录、旧版本或不在当前检索范围的来源不猜测映射，必要时要求补充资料标题。
  数据库中的历史正文、引用编号和原文快照不被改写。
- 重试同时提供待修正候选和 Judge 反馈，将反馈中的本轮 C 编号转换为稳定标识。
- Judge 仍检查陈述是否由引用支持。稳定身份解决编号歧义，不保证模型一定选择正确资料。
  联网模块继续沿用现有路径，本次不扩展其质量优化。
