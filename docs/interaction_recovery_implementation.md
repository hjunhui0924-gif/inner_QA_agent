# 等待、流式预览与恢复操作修复

## 审查后的方案

本轮修复基于 `5e7aa19` 和 [真实用户走查](user_experience_walkthrough_2026-09-27.md)。审查确认原来的等待来自两层缓冲：后端整条流程完成后才发送答案片段，前端只展示最终 result。因此不能只改前端文字动画。

审查后收紧了四项契约：

1. 普通通用回答用独立的预览事件，不复用已有 token，更不转发路由、摘要或 Judge 模型的通用流事件。
2. `web_search=false` 必须确实禁止联网，不能被“搜索、最新”等关键词或模型路由结果重新开启。
3. 重试使用新 turn_id，原结果保留，关联写入已完成结果；取消或断网的父请求不要求已存在于数据库。所有历史关联限于当前用户和会话。
4. 未填写的业务日期必须与检索边界值区分；不能把所有真实 1970 日期一律隐藏。

## 最终行为

- 等待阶段、计时、处理详情和取消按钮移至正在回答的消息处。手机展开步骤发生在对话滚动区内，不再挤占输入框上方的固定空间。完成后移除当前处理面板。
- 等待期间可编辑下一条草稿，但不能并发发送；取消、完成和跨页不清空新草稿。
- 取消后有重新生成和编辑问题；已有草稿时提供替换/保留选择，切换会话会清除待确认的编辑，避免跨会话误覆盖。
- 失败只展示一份简明错误卡片，恢复动作可见。失败、资料不足及搜索无结果均可编辑；搜索失败/无结果可由用户选择关闭联网继续问答，提示无法保证最新信息。
- 消息使用响应式对象更新。用户位于底部时随正文、预览及错误状态更新滚动；主动上翻时保持位置并保留回到最新回答入口。
- 重试按同一问题折叠，之前的尝试可展开；数据库保留所有正式结果，刷新后仍恢复分组。文字相同但没有重试关联的普通提问不会自动合并。
- 知识管理页显示后台回答状态和查看入口，不自动跳转打断当前操作。
- 新上传未填日期显示“未指定生效日期”；明确填写 1970-01-01 仍如实展示。历史无来源标记的 1970 日期注明待核实，保留截止日期。检索索引边界保持兼容。

## 协议和数据变化

`generate` 仅在 `mode=general`、实际路由 `direct`、未联网时派发 `general_preview_delta` 自定义事件。API 再检查模式、联网开关、路由和节点，只转为以下 SSE：

```json
{"type":"preview_delta","content":"增量文字","generation_id":"本次生成标识"}
```

前端将预览保存在 `previewContent`，标为“生成中 · 尚未完成”；不同 generation_id 重置预览。正式 `result.content` 替换并清除预览。知识库及联网模式忽略预览，既有 `token` 仍不直接交付正文。中断的通用预览显示“未完成草稿”，不提供正式答案复制或引用操作，也不作为已完成答案写入数据库。

取消只代表前端停止等待，不承诺供应商计算/计费回滚；在服务器已经完成提交的边界上，刷新可能读到正式结果。收到 result 后的断线或取消不能覆盖正式结果。

请求新增可选 `attempt_group_id`、`retry_of_turn_id`；每次尝试仍使用新的 `turn_id`。`chat_turn_results` 启动时增加向后兼容的 `metadata_json`，随正式结果保存重试关联、mode/web_search、失败分类、阶段及 trace_id。历史通过同用户、同会话、同 turn 的关联读取元信息；幂等回放保留原失败类型，不再把失败结果伪装成成功。旧记录仍可读取，不推断未知的历史重试关联。视图折叠不等于删除历史或清除模型上下文。

知识上传保留 `effective_from_provided` 标记，列表和详情都返回它；已有数据没有该标记时保持兼容。

## 验证结果

- 后端完整套件：`python -m pytest tests -q`，**239 passed、2 skipped**。只有既有 python_multipart 弃用警告。
- 前端完整套件：`npm --prefix frontend test`，**90 passed**；最后的历史截止日期修正另有定向测试通过。
- `npm --prefix frontend run build` 通过，包含 TypeScript 检查。
- `tests/e2e_product_experience.py` 通过：14 个首页布局、IME、引用身份/焦点、草稿/滚动、跨页流式任务、慢会话列表、上传跨页和 100 文档过滤。
- `tests/e2e_experience_edge_cases.py` 通过：真实 200% 浏览器缩放、模拟触控/嵌套面板、24 个错误与流边界场景。
- 独立静态审阅提出并修复日期列表漏字段、无搜索结果缺恢复按钮、编辑确认跨会话污染、历史截止日期遗漏四项问题。

真实 Chrome + DeepSeek v4 Pro 验收使用隔离 SQLite、Chroma 和上传目录，9 项检查通过，页面错误监听为零：上传日期、RAG 正式交付与可编辑草稿、追问引用、预览及取消、编辑确认会话隔离、后台完成、手机重试可见/折叠、刷新恢复及明确关闭联网、浏览器错误检查。

本次约 2000 字通用请求 **2.41 秒出现预览**，随后主动取消验证恢复操作。此前走查同类长请求等待 24 秒仍无正文。两次不是同一请求的性能基准，不能推导固定提速倍数或保证每次 2.4 秒。此次知识库首问操作耗时约 8.7 秒，仍等待校验后交付；没有声称减少了其完整回答耗时。
