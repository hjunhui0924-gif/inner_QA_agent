# 企业知识工作台前端设计

日期：2026-09-12。

## 目标与参考

服务于员工查制度、找流程、核对原文，以及管理员维护知识文档。主要使用距离是桌面办公距离，同时覆盖手机；强调安静、清晰和信息可核对。

本次读取并参考的官方资料：

- [Notion Enterprise Search](https://www.notion.com/product/enterprise-search)：检索入口、简洁结果列表、来源范围和引用。查看了官方页面中的搜索结果及来源选择界面图片。
- [Glean Assistant](https://www.glean.com/ai-assistant)：围绕工作问题组织入口，以公司知识提供带依据的结果；参考其产品描述，未登录体验后台。

借鉴信息层级与交互原则，界面使用本项目自己的品牌和组件，不复刻第三方商标，也不添加尚未实现的连接器、权限选择或反馈按钮。通用网页阅读代理连接超时后，直接读取以上公开官网核实资料。

## 设计系统

浅灰白底色 `#F8F9FC`、白色内容面板、浅灰侧栏 `#F3F5F9`；正文 `#202634`，主色钴蓝 `#3458CF`。正常、警告和错误使用独立语义色，不用主色暗示事实已被验证。

中文无衬线字体栈采用本地系统字体；对话正文 15px，手机输入 16px，常规页面标题约 25～30px。间距以 4/8px 为基础，控件圆角 8px、内容面板 14～16px。阴影只用于层级区分；微交互 160～220ms，遵循 `prefers-reduced-motion`。

## 核心调整

1. **输入优先。** 对话工作区固定为 `100dvh`，采用标题、可滚动消息、输入区三行布局。旧版 1440×900 首屏的输入框顶部约为 1087px；新版完整留在首屏。窄屏、横屏及展开处理过程都要满足该约束。
2. **答案优先。** 用户消息用浅灰气泡，助手答案按文档排版。过程默认只有一行，可展开；手机横屏的过程浮在输入区上方。支持复制 Markdown 答案、已复制反馈和失败提示。
3. **阅读不中断。** 只在用户靠近消息底部时自动跟随新内容。用户上翻阅读时保留位置，提供“回到最新回答”。会话切换清理旧引用面板，从知识库返回时定位到当前会话最新内容。
4. **文档列表优先。** 文档名称、部门、版本、生效状态、来源、日期和负责人集中在列表；搜索筛选始终在前。上传通过右侧抽屉进入，可选元数据折叠展示。抽屉复用现有 overlay 栈，支持焦点循环、Escape、背景隔离和返回触发按钮。
5. **来源可理解。** 保留逐字引文、文件名、页码和章节；将常见来源、部门和校验状态转为中文。`provenance_only` 显示“已核对引用出处”，不升级成语义正确结论。未知校验状态提示用户核对原文。
6. **减少首屏负担。** Element Plus 仅注册并加载 `ElIcon` 及其样式，两个路由页面动态导入。图标包成为直接依赖。样式拆为公共基础、对话、知识库、浮层四个文件，避免继续在大文件尾部堆覆盖规则。

## 验证

- `npm run build`：包括 TypeScript 检查和生产构建。
- `npm run test`：已有 60 项测试，上传相关测试改为操作真实抽屉入口。
- `python tests/e2e_mvp_browser.py`：保留问答、模式切换、引用、继续追问、删除、上传、筛选、详情和下载验收。
