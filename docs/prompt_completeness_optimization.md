# 系统提示词：完整后再精简

2026-09-13。本轮针对上一轮 `dsl_05` 生成遗漏“及时告知用户”的问题，调整 RAG、通用问答和原生搜索的系统提示词。

## 原因与调整

原始引用 C1 已包含“立即采取处置措施，按照规定及时告知用户并向有关主管部门报告”。模型合并其他条款时漏掉了告知用户，说明该次遗漏发生在生成阶段。原提示词多次强调固定句数、最小信息和首句后停止，却没有明确要求列举问题覆盖全部必要动作。这是可调整的风险因素，不是对模型内部行为的确定性解释。

新提示词以这条规则为首要要求：

> 优先保证事实准确、必要信息完整和引用可追溯，再精简表达；不得为了缩短篇幅省略关键内容。

- 按用户实际询问的范围，完整回答所有子问题；措施、材料、条件、职责和流程逐项覆盖。
- 保留主体、动作、对象、期限、金额与单位、前置条件、例外、步骤顺序及“且/或”关系。
- 多来源只合并含义和适用范围一致的重复信息，保留各段独有要求；不同主体、版本和条件分别说明。
- 单一事实把结论和必要条件合成一句，多项要求用平级短列表，不以固定句数限制必要内容。直接给出带引用的答案，避免重复导语、无引用总结句和嵌套列表。
- 每个事实句或列表项紧跟引用，开头的肯定或否定结论也不例外。
- 输出前核对覆盖情况，仅输出最终回答；重试提示允许依据现有证据补全遗漏，而不只是删除内容。

生成提示词位于 `backend/agent/nodes.py`，原生搜索提示词位于 `backend/agent/web_search.py`。未更改模型、检索参数或评测判定规则，未加入失败题目的专有答案。

## 验证方法

使用与上轮相同的 34 题官方政策开发集、向量模型、重排和生成/Judge 模型，完整执行真实检索、单次生成与自动 Judge。索引使用隔离副本，业务知识库与历史报告不变。前后模型服务调用发生在不同时间，结果可能波动。

本轮报告目录：`work/backend-verification/prompt-completeness-20260913-001042/`，其中 `run_benchmark.py` 可重跑本次隔离评测，`nodes-before.py` 和 `web_search-before.py` 保留修改前源码用于核对。通用模式、网页来源、上传和引用恢复另由真实前后端联调覆盖。

首轮提示词复测 `report.json` 的自动 Judge 为 34/34，但严格引用完整性从基线的 98.33% 降为 92.67%。逐题复核发现无引用的开头结论、承载事实的小标题和超出提问范围的扩展。因而继续收紧范围和输出格式，明确仅覆盖本题要点，用带引用的平级短列表，删除重复总结。首轮结果及源码 `nodes-first-pass.py` 保留，没有以单个 Judge 分数作为验收依据。

最终版本使用 `run_refined_benchmark.py` 运行，结果另存 `refined/report.json`，未覆盖首轮数据。两次评测仅调整生成提示词；检索、模型和 Judge 规则相同。

原生搜索额外冒烟中有一次 `web_search_unavailable`，随后重试成功，分别保存为 `web-smoke.json`、`web-smoke-retry.json`。最终完整联调的联网检查均成功，但仍观察到简单定义回答偶发补充历史背景；不能将接口通过等同于完全遵循精简要求。

## 保留的失败与取舍

- `genai_02` 仍以无独立引用的“不适用。”开头，解释句有引用，严格逐句指标为 0.5；现有生产引用校验允许紧接引用解释的简短结论，因此该检查通过。没有为了抹掉差异而修改任何校验器。
- `dsl_04` 的首句未绑定引用，还补充了原文未明确说明的“未规定后续的申诉或复议程序”。自动 Judge 将该推论判通过，逐题复核时将其作为真实问题保留。现有生产引用校验会因首句缺引用拒绝该候选，进入原有修正流程；未对该题重跑完整生产流程。
- `dsl_04` 同时因“未规定”触发确定性拒答关键词，评测归类为 `refusal_failure`，实际并非无答案题拒答失败。最终四个无答案题均正确拒答。
- 最终报告归因计数为 10 个 `generation_failure`、1 个 `citation_failure`、1 个 `refusal_failure`、22 个 `none`。生成调用没有错误，10 个生成归因来自严格短语/语义关系代理匹配；该归因有优先级，不表示只有一题的引用指标低于 1。`dsl_05` 虽含标准短语，也受整段关系检查影响被扣分，原始分数完整保留。

本轮改善了已发现的要点遗漏，并将首轮过度展开的平均长度从 196.0 字符压到 136.3 字符，但仍高于原先的 58.3 字符；严格引用完整性也尚未恢复到原基线。因此不宣称所有指标改善或质量验收全部通过。后续应在独立留出题上验证完整性，并校准自动 Judge 对无证据推论的判断，不应只追求同一开发集的 100% 自动评分。

## 能力边界

2026-09-13 发布前追加了固定证据下的正式节点回放（`work/release-verification-20260913-004631/quality-replay.json`）。`dsl_04` 初始候选和一次重新生成均被引用校验拒绝，最终安全降级；`dsl_05` 保留“告知用户”并通过，`genai_02` 通过现有短结论规则。此次验证补充了此前未知的校验、重试和最终交付行为，没有消除单次生成评测中的质量问题，也没有重跑这三题的完整检索和路由。

输出前自查是提示词约束，不是新增的独立完整性校验器。系统仍可能遗漏信息；同模型自动 Judge 和参与迭代的开发集不能代替独立人工评估。引用出处检查也不能单独证明要点齐全。本轮不通过放宽评测标准获得更高分数。
