# RAG 检索优化设计

## 目标

本轮优化不以“用了多少技术”为目标，而以可证伪的检索质量改进为目标：在包含
多份同主题权威文档、精确数字、相似条款和干扰文档的固定评测集上，证明每个检索
阶段的边际收益，并记录延迟成本。

## 检索链路

```text
query
  ├─ BM25 lexical recall ─┐
  └─ dense recall ────────┤
                          └─ RRF fusion → unique candidates
                                                ↓
                                      cross-encoder rerank
                                                ↓
                                             top-k
```

### 不变量

1. BM25 与向量召回独立运行，各自返回候选排名。
2. RRF 只使用排名，不直接混合不可比较的原始分数。
3. 候选以稳定 `chunk_id` 去重。
4. Rerank 只接收融合后的有限候选，超长内容在适配器内部截断。
5. Rerank 超时、限流或返回无效数据时，返回 RRF 结果并记录降级原因。
6. 生产调用只依赖 `retrieve(query, top_k)`；评测可以选择阶段进行消融实验。
7. Embedding 配置、切块参数和文档语料摘要共同决定索引身份，禁止新旧向量混用。

## 评测框架

检索评测至少比较：

- `dense`：仅向量召回；
- `lexical`：仅 BM25；
- `fusion`：BM25 + 向量 + RRF；
- `rerank`：BM25 + 向量 + RRF + Rerank。

核心指标：

- `source_hit@k`：目标来源是否进入 Top-K；
- `evidence_recall@k`：标准证据短语覆盖率；
- `MRR@k`：首个相关来源排名；
- `nDCG@k`：相关来源的排名质量；
- P50/P95 延迟；
- Rerank 降级次数。

回答正确率、忠实度、引用准确率属于生成评测，不与检索指标混成一个分数。

## 可信测试语料

测试语料只接受原始官方域名，下载时保存来源 URL、发布机构、抓取时间和正文
SHA-256（文本换行统一为 LF），并与人工核验后固定在 manifest 中的摘要比对。中国人大网两个原始页面
仅提供 HTTP，因此固定摘要用于发现传输内容变化，但不能替代 HTTPS 的传输安全。
首批文档均围绕数据治理，词汇高度重合，可以形成真实干扰：

- 中国人大网：《中华人民共和国个人信息保护法》；
- 中国人大网：《中华人民共和国数据安全法》；
- 国家互联网信息办公室：《生成式人工智能服务管理暂行办法》；
- 中国政府网：《网络数据安全管理条例》。

## 验收条件

1. 四种检索策略在同一语料、同一 Chunk、同一 Top-K 下运行。
2. Rerank 适配器有真实 DashScope 集成测试和确定性测试替身。
3. 远程 Rerank 故障不会导致问答失败。
4. 评测数据包含精确事实、数字/日期、相似条款和无答案问题。
5. 报告包含配置与语料摘要，结果可复现。
6. 最终结论依据消融结果；如果 Rerank 没有稳定收益，则默认关闭。
