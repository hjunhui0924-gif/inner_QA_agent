# RAG 检索优化设计

## 目标

本轮优化不以“用了多少技术”为目标，而以可证伪的检索质量改进为目标：在包含
多份同主题权威文档、精确数字、相似条款和干扰文档的固定评测集上，证明每个检索
阶段的边际收益，并记录延迟成本。

## 检索链路

```text
query
  ├─ BM25 lexical recall ─┐
  └─ dense recall ────────┤
                          └─ RRF fusion → unique candidates
                                                ↓
                                      cross-encoder rerank
                                                ↓
                                             top-k
```

### 不变量

1. BM25 与向量召回独立运行，各自返回候选排名。
2. RRF 只使用排名，不直接混合不可比较的原始分数。
3. 候选以稳定 `chunk_id` 去重。
4. Rerank 只接收融合后的有限候选，超长内容在适配器内部截断。
5. Rerank 超时、限流或返回无效数据时，返回 RRF 结果并记录降级原因。
6. 生产调用只依赖 `retrieve(query, top_k)`；评测可以选择阶段进行消融实验。
7. Embedding 配置、切块参数和文档语料摘要共同决定索引身份，禁止新旧向量混用。

## 评测框架

检索评测至少比较：

- `dense`：仅向量召回；
- `lexical`：仅 BM25；
- `fusion`：BM25 + 向量 + RRF；
- `rerank`：BM25 + 向量 + RRF + Rerank。

核心指标：

- `source_hit@k`：目标来源是否进入 Top-K；
- `evidence_recall@k`：标准证据短语覆盖率；
- `MRR@k`：首个相关来源排名；
- `nDCG@k`：相关来源的排名质量；
- P50/P95 延迟；
- Rerank 降级次数。

回答正确率、忠实度、引用准确率属于生成评测，不与检索指标混成一个分数。

## 可信测试语料

测试语料只接受原始官方域名，下载时保存来源 URL、发布机构、抓取时间和正文
SHA-256（文本换行统一为 LF），并与人工核验后固定在 manifest 中的摘要比对。中国人大网两个原始页面
仅提供 HTTP，因此固定摘要用于发现传输内容变化，但不能替代 HTTPS 的传输安全。
首批文档均围绕数据治理，词汇高度重合，可以形成真实干扰：

- 中国人大网：《中华人民共和国个人信息保护法》；
- 中国人大网：《中华人民共和国数据安全法》；
- 国家互联网信息办公室：《生成式人工智能服务管理暂行办法》；
- 中国政府网：《网络数据安全管理条例》。

## 验收条件

1. 四种检索策略在同一语料、同一 Chunk、同一 Top-K 下运行。
2. Rerank 适配器有真实 DashScope 集成测试和确定性测试替身。
3. 远程 Rerank 故障不会导致问答失败。
4. 评测数据包含精确事实、数字/日期、相似条款和无答案问题。
5. 报告包含配置与语料摘要，结果可复现。
6. 最终结论依据消融结果；如果 Rerank 没有稳定收益，则默认关闭。

## 回答与引用链路

检索命中不等于回答可信。生成阶段把每个候选 Chunk 标记为 `[C1]`、`[C2]`，要求事实、数字、日期和规则逐句引用；生成完成后只做保守的编号范围、数字/关系冲突和近逐字子句检查。系统不会为无引用断言自动补造或重分配引用，但这些确定性检查仍不等同于语义蕴含证明；缺少有效出处或未通过独立幻觉检查的 RAG 回答会失败关闭。

结构化引用包含 `document_id`、标题、来源、原始文件名、页码、章节、`chunk_id`、逐字原文摘录和 `verification_status=provenance_only`。它只证明引文出处，不宣称原文蕴含回答；语义支持由独立幻觉检查节点判断，校验模型不可用时关闭放行。PDF 解析按页保存 Segment，Markdown 与 DOCX 按标题保存 Section；Segment 在切块和向量持久化后仍保留位置元数据。SSE 的 `result` 事件返回最终答案、引用、Trace ID 和运行时失败类型。Vue 3 + Vite + TypeScript 工作台已接入真实 SSE、结构化引用、会话生命周期、文件上传和知识库接口，是项目唯一 Web 前端。

## 答案级评测与失败闭环

`scripts/run_answer_benchmark.py` 使用同一套权威法规开发集执行检索和单次生成，分别计算 Gold Phrase 匹配、数字匹配、引用出处准确率、引用完整性、抽取重合率和拒答匹配率。出处准确率只验证摘录确实来自对应 Chunk；抽取重合率只衡量近逐字出现，二者均不等同于人工或 NLI 蕴含判断。该脚本不经过路由、查询改写、幻觉重试和安全 fallback，因此不宣称代表完整生产 Agent。

每次线上问答可写入有界 JSONL Trace，保存问题、最终答案、召回 Chunk 摘要、引用、节点轨迹和失败类型。运行时可识别检索缺失、生成失败与引用失败；评测环境结合 Gold Evidence 进一步区分解析失败、召回失败、排序错误、生成错误、引用错误和拒答错误。

当前回答生成模型与自动 Judge 默认均为 `qwen3.6-plus`，分别由 `MODEL_NAME` 和 `JUDGE_MODEL_NAME` 配置。两者保持独立配置，是为了后续使用不同模型交叉评判，降低同模型自评偏差。评测执行和指标计算全自动完成；现有 34 题属于开发集，后续新增样本采用模型生成、原文包含校验与冲突样本自动剔除，尽量减少人工标注。

当前 34 题自动评测中，Judge 回答正确率为 100%，Grounded 与引用语义支持率均为 94.12%，无答案拒答正确率为 100%，四项全部通过率为 94.12%。确定性的数字/日期匹配、引用出处准确率和引用完整性均为 100%。剩余 2 个失败样本均为核心答案正确但补充了引用未覆盖的信息；报告保留失败详情，不将其人工改判为通过。
